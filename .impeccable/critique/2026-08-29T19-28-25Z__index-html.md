## Design Specificity Verdict

**Split, and the split is the story.** The printed Bauauftrag is unmistakably authored for THW Fernmeldebau. The application shell is a generic Leaflet editor.

**LLM assessment**: `print.css` + `bauauftrag.js` could not have been written by someone who hasn't handed a sheet of paper to a Fernmeldebautrupp — Nordpfeil, computed "Maßstab ca. 1 : 14.000", Übersichtskarte inset, per-point MGRS *and* GPS *and* Teilstrecke *and* Σ, a ruled "Zusätzliches Material" box left deliberately blank, four Unterschriftenfelder, "Blatt 1 von 2". The S/W mode swaps to the BKG-Graustufenkarte and re-encodes Strecken by stroke pattern instead of colour, because the real delivery medium is a photocopy in a vehicle. The map, by contrast, is the default composition of every browser GIS editor since 2014: tool rail top-left, options card top-right, coordinate strip along the bottom, list sidebar left. Swap the German strings and the `KABELTYPEN` table and you have a hiking-route planner.

Sharpest evidence: `kennzahlen()` computes `trommeln = ceil(bedarf / trommellaenge)` — "5 Trommeln" — and the map draws nothing. The positions where the drum runs out and the next joint must be made are fully derivable and are *the* thing a Bautrupp walks the line looking for. The app knows the number and refuses to show the places.

**Deterministic scan**: CLI `detect.mjs --json index.html` → **exit 0, zero findings** — but nearly vacuous: `index.html` is a 171-line shell and the entire UI is built at runtime by `js/ui.js` and `js/bauauftrag.js`, which the static engine never executes. Browser injection (live-server port 8400) is the load-bearing evidence:

- Default view, **4 anti-patterns**: `gpt-thin-border-wide-shadow` ×2 (`#menu-datei` app.css:114–115, `#zeichen-hinweis` app.css:321–322) — genuine; `dark-glow`, `clipped-overflow-container`, `overused-font` — all false positives (see below).
- Strecke open, **7 `text-occlusion` findings** — genuine and visible in screenshots: `span.fbp-punkt.art-start "1A"` 100% covered, `art-ziel "4E"` 100% covered, `art-muffe "3M"` 50% covered by `span.tz-label`, `seg-mass "1.178 m"` 83% covered by `path.leaflet-interactive`.
- Bauauftrag open, 91 findings, of which 44 in-`.blatt` typography flags are false positives.

**False positives confirmed by measurement**: `overused-font: roboto` — Roboto is the 4th fallback in a system stack and a width probe proves it isn't the resolved face. The 44 `undersized-ui-text`/`tiny-text` findings inside `.blatt` — that element is 1123×794 CSS px at 1:1 mm, i.e. A4 paper at `8.6pt` base; the detector's 10–11px *screen* floor doesn't govern print. `clipped-overflow-container` on `#karte` — vendor Leaflet, load-bearing. `dark-glow` on `#menu-datei` — an 8px-offset elevation shadow on a white menu that was `display:none` at scan time.

**Visual overlays**: injection succeeded and the detector ran in-page, but both servers were stopped before reporting, so no overlay tab is currently open for you to look at. The console output above is the record.

## Overall Impression

You have built one genuinely excellent thing and wrapped it in scaffolding. The Bauauftrag is a document, not a screenshot, and it will be why people recommend this tool. Everything around it is standard-issue map-editor chrome with three real defects underneath: Ctrl+P prints a blank page, the riskiest property of the product (localStorage-only, no account, no backup) is disclosed in a third tab in 12.5px grey, and the destructive actions are weighted inversely to their actual risk.

The single biggest opportunity: make the *map* as domain-specific as the printout. Draw the Trommelstöße. Add a `status` enum. Right now the map is where the work happens and it's the part that knows the least about Fernmeldebau.

## What's Working

**1. The Bauauftrag as a real form.** `bl-kopf` with Auftrag-Nr./Datum/"Blatt 1 von 2", six stamped `bl-stamm` fields, a bordered `karten-rahmen` with its own Nordpfeil and Maßstabsleiste, a `mat-frei` box left blank for the trupp to write in, `us-gitter` with four signature blocks. And it renders at 2× and halves it in CSS (`SCHAERFE = 2`) for ~190 dpi instead of 96 — someone looked at a printout and was annoyed by it.

**2. Defaults that carry domain knowledge and then get out of the way.** `KABELTYPEN` attaches `trommel`/`zuschlag`/`leistung` per cable type — LWL gets 20 % Bauzuschlag against 15 % for Feldkabel, because it does — and ui.js:196–203 pulls those through on a type change *only if the user hasn't manually overridden them*. Invisible when it works, which is the mark of it being right.

**3. The drawing-mode bar.** `#zeichen-hinweis` names the Strecke, counts points live, and prints all three exits on the buttons with their keys: `Letzten Punkt zurück` / `Fertig (Enter)` / `Abbrechen (Esc)`. One mode, no hidden state, nothing to memorize. Measure the rest of the app against this bar.

## Priority Issues

### [P0] Ctrl+P prints a blank page, and the `@page` override leaks permanently
**Why it matters**: Ctrl+P is the reflex for "print this" in an app whose entire purpose is printing. `print.css` is loaded `media="all"` and its `@media print` block hides `#app` unconditionally (print.css:245); with no `#druck` in the DOM you get an empty sheet — verified live. Separately, `drucken()` injects `<style id="druck-seitenformat">@page{size:297mm 420mm;margin:0}</style>` (bauauftrag.js:502–510) and never removes it, so after one A3-quer Bauauftrag every later print in that tab is silently forced to A3 landscape, zero margins — including a subsequent A4 Bauauftrag.
**Fix**: Scope the rule to `body.druckansicht #app { display:none !important }`. Remove `#druck-seitenformat` in `schliesseBauauftrag()`. Optionally intercept `beforeprint` when no Bauauftrag is open and route to the selected Strecke's print view instead.
**Suggested command**: `/impeccable harden`

### [P0] The data-loss risk is disclosed in the wrong place, at the wrong time, at the wrong size
**Why it matters**: localStorage-only, single browser, no account — the product's one unrecoverable failure mode, disclosed once in Reiter 3 → "Speicher" at 12.5px grey (ui.js ~628). No first-run mention, no persistent indicator, no nudge to export after real work. The people most likely to hit it — a shared Übungs-Laptop, a browser set to clear on exit, an incognito window — are precisely the field/exercise scenario this tool targets. The `speicherfehler` path is the right instinct but fires *after* the write already failed. `speicherBelegung()` reports "Aktuell belegt: 340 kB" — a number with no denominator against the ~5 MB quota.
**Fix**: (a) Replace the first-run Kurzanleitung modal with a persistent one-liner under the header — *"Diese Planung liegt nur in diesem Browser. Sicherung: Datei → Planung als Datei sichern."* — with the export action inline. (b) Make `#speicherstatus` clickable-to-export and give it a third amber state, `zuletzt als Datei gesichert: —`, once a project has ≥2 Strecken and has never been exported. (c) `beforeunload` → `preventDefault()` when never exported and the project is non-trivial.
**Suggested command**: `/impeccable harden`

### [P1] Destructive actions are weighted inversely to their actual risk
**Why it matters**: Three deletions, three treatments, in exactly the wrong order. **Trassenpunkt** (ui.js:371–384): a 24×24 `✕` five pixels from the `⌖` "show on map" button — instant, silent, no toast, no mention of undo; *recoverable*. **Strecke** (ui.js:270–283): a custom modal naming the Strecke and its point count plus "Rückgängig machen ist mit Strg+Z möglich."; *recoverable*. **Gespeicherte Planung** (ui.js:666): a native `confirm()` — the one dialog users are trained to dismiss reflexively — and `store.loeschen()` clears `undoStapel`; **unrecoverable**. Gloved, the 5px gap between `⌖` and `✕` is a coin flip between "zoom to this point" and "delete this point", and only one of those tells you it happened.
**Fix**: Invert the weights. Point delete: keep it instant but emit `hinweis('Punkt 3 gelöscht — Strg+Z macht es rückgängig')`, and move `✕` to the right edge past the coordinate row. Planung delete: promote to the custom `dialog()` with type-to-confirm on the project name and "Vorher als Datei sichern" as the escape in the same footer.
**Suggested command**: `/impeccable harden`

### [P1] The narrow layout breaks the header and strands the user off the map
**Why it matters**: Measured live at 375px: `#projektname` collapses to **22px** (154..176) while `#btn-undo` renders at 168..206 — they overlap. `.marke` and `.kopf-tasten` are both `flex-shrink:0` and `.speicherstatus` is `white-space:nowrap`, so the project name is the only element allowed to give. Compounding it, app.css:526 sets `visibility:hidden` on the whole `.kartenbereich` while the sidebar is open, so the only route back to the map is a 37px `☰` sharing pixels with a text input. And `#sl-mgrs` is written only by `karte.on('mousemove')` — on touch there is no mousemove, so the MGRS readout, the single most valuable feature to a field user, is permanently `–` on the device where it matters most.
**Fix**: In the `max-width:900px` block: drop `.marke-text`, hide `#btn-undo`/`#btn-redo`, reduce `#speicherstatus` to a dot, give `#projektname` a `min-width:120px`, and keep the `.wz` labels as a 2×2 icon+label grid. Bind `#sl-mgrs` to `click`/`touchend` as well as `mousemove`, and show the coordinate of the last tapped position.
**Suggested command**: `/impeccable adapt`

### [P2] The map is generic where the printout is specific
**Why it matters**: `kennzahlen()` computes "5 Trommeln" and the map never shows where the joints land. There is a `querung` Punktart with its own diamond glyph and nothing ever flags an unmarked road or rail crossing. Nothing distinguishes geplant / beauftragt / im Bau / gebaut. And the detector confirms the map's labelling is already over capacity: 7 `text-occlusion` findings, with `1A` and `4E` 100% covered and `seg-mass "1.178 m"` 83% covered by its own route path. The map is where the work happens and it's the part that knows the least about the domain.
**Fix**: Draw a distinct marker at each trommel boundary derived from the segment lengths plus Bauzuschlag, with its MGRS in the Punkttabelle. Add a `status` enum to `neueStrecke()` and encode it with the stroke patterns you already wrote for the S/W print. Give labels collision-aware placement (offset or leader lines) before adding more of them.
**Suggested command**: `/impeccable shape`

### [P2] The primary output is buried, and the print handoff offloads state onto the user
**Why it matters**: `▤ Bauauftrag (PDF)` sits at scrollTop ≈1400 of a 1522px sidebar, below Kennzahlen, Stammdaten, six technical fields, the full Punktliste and a four-button action row — and it shares equal visual weight (blue `breit`) with `Strecke löschen` (red `breit`) directly adjacent. The Bauauftrag *is* the product and it's the one control you have to hunt for. Then `window.print()` hands off to the OS dialog where the user must independently re-select A4/A3 and Hoch/Quer — an instruction that lives in the help text and the README rather than in the flow. The README and the help both spell it out, which confirms the app knows it's offloading state.
**Fix**: Pin the Ausgabe row with `position:sticky; bottom:0` so it never scrolls away, and demote `Strecke löschen` out of `breit`. Put the format reminder in the print button's immediate context, generated from the current `opt`: **"Im Druckdialog: A4, Quer, Ränder ‚Keine'"**.
**Suggested command**: `/impeccable layout`

## Questions to Consider

1. **Why does the map know the Trommelzahl but refuse to draw the Trommelstöße?** You compute `ceil(bedarf / trommellaenge)` and you have every segment length. Rendering a marker at each drum boundary — with its MGRS in the Punkttabelle — turns "5 Trommeln" from a number into a plan, and it's the single change that would make the map as domain-specific as the printout.
2. **What if the Bauauftrag were the app, and the map a panel inside it?** If the sheet were the persistent right-hand surface updating live, the print handoff stops being a leap of faith, the "remember A4/Quer" instruction becomes unnecessary, and every field in the Projekt tab acquires a visible consequence as you fill it.
3. **You have `sichtbar`, `art` and colour per Strecke — where is `status`?** geplant / beauftragt / im Bau / gebaut / gestört. One enum makes the map answer the question a Zugführer actually asks it, and it costs one field plus one stroke-pattern rule you already wrote for the S/W print.
4. **If localStorage is genuinely the storage model, why isn't the `.json` file a first-class citizen?** The File System Access API would bind "Planung als Datei sichern" to a real file once and autosave to it — same zero-server, zero-login guarantee, and your single biggest product risk disappears.
5. **What would this look like if it opened at the user's Ortsverband instead of at Germany?** One `getCurrentPosition()` on first run, or a remembered "Heimatstandort", deletes the coldest 30 seconds of the first-run experience.
6. **The `⌖` and the `✕` sit five pixels apart in a tool used with gloves in daylight. Which of those did you assume would be pressed more often?** Nothing in the layout reflects an answer.
